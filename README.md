# Wholebody Studio — フェーズ3
映像から全身・手指・足先を推定し、端末内のVRMへ反映するPoC。足だけの入力にはGoogleの学習済み点追跡BootsTAPIRを使う。映像の精度、モデル変換の一致、VRMの描画、実時間性能を区別して表示する。
## フェーズ3の追加
- [操作手順](docs/phase3-usage.md) / [Node.jsとOSCブリッジ](docs/phase3-bridge.md) / [測定範囲](docs/phase3-results.md)
- 全身の既定モデルはRTMW3D-X。足だけの入力では全身モデルを読み込まず、FOCUSの足先候補または手動3点からBootsTAPIRを初期化する。
- 初期点は母趾先・小趾先・踵中心。意味付けは検出器または本人の指定が担い、BootsTAPIRはその画像点を追う。手動初期化の成功を自動検出の成功と呼ばない。
- 推論はDedicated Worker内のONNX Runtime Webで実行。WebGPUでは特徴と時系列状態をGPUバッファに保ち、最後の3点と可視性をCPUへ戻す。WASMも選択でき、backendの失敗を黙って別backendへ切り替えない。
- 通常再生は最新フレームだけを処理する。遅い録画解析には「動画を順送り解析」を使い、推論完了後に動画時刻を1/30秒進める。30Hzの時刻サンプルであり、元動画の全フレームの正確な復号や実時間再生を保証するものではない。
- 初期3点の周辺を固定範囲で拡大する比較機能は既定OFF。足が範囲を外れると欠測になるため、全動作で有利な設定とはしない。
- 埋め込みアセットを持つVRM 0.x / 1.0をローカルで読み込み、実ボーンとスキン頂点を動かす。WebGLがない場合もCPU簡易描画を使える。外部配布モデルは同梱しない。
- 自作サンプルVRMと明示操作の表示確認用デモを備える。人工動作は紫の表示を付け、精度評価・計測記録・VR出力には使わない。
- 足だけ・未校正の入力からは画像平面内の足の回転を反映する。観測していない上半身は基準姿勢とし、奥行きや独立した5本の足指の関節を測ったとは扱わない。
- 任意のローカルNode.jsブリッジはWebSocketからVMTのOSC UDP形式へ変換する。絶対位置とルーム座標の校正が揃うまで有効な位置を送らない。

## フェーズ2の固定標本と測定結果
以下の静止画成績はRTMW-l経路の結果であり、現在のRTMW3D-Xや足の点追跡の動画精度へ読み替えない。
既定は人物自動検出ON・手の選択採用ON・足専用モデルの補正OFF。調整用4画像を除外した固定32画像を、人物検出から通して評価した。通常画像のPCK@0.2は身体91.2%、手75.4%、足60.5%。手は本体だけの74.7%から小幅改善したが、覆った手の点だけでは改善していない。足専用の補正は通常画像で60.5%→56.7%、足遮蔽画像で51.6%→43.3%へ回帰したため既定には採用しない。
数値の分母は身体477点・手1,132点・足157点。PCKの正規化は部位ごとに異なり、静止画上の2D精度である。詳細レポートには画素誤差・未検出・人物の取り違え・画像別の悪化も残している。全ての手や遮蔽条件で改善したという主張ではない。
## 実装
YOLOX-tinyで人物を特定し、初回は最大の人物、以後は直前の対象と重なる候補を追う。手動で囲った人物範囲を優先し、人物未検出を欠測として扱う。
全身モデルの既定はRTMW3D-Xで、RTMW-lとRTMPose-s FP32も比較用に選べる。手指は元解像度の映像から予測ROIを切り出し、RTMPose Hand5で再推論する。手首との位置関係、手首と指のモデル出力、切り出し境界への集中を判定し、条件を満たす候補だけを採用する。異なるモデルのrawスコアの大小を比べて置き換えない。
足の比較経路はFOCUS one2manyの8点出力を利用する。人物全体の範囲を入力し、同側の膝・足首との位置整合と足の長さを確認して、採用された足先6点を元の推定と50%ずつ混ぜる。足首の推定位置は置き換えない。足だけの切り出しや候補の単純な置き換えは実画像で悪化したため、失敗結果も残している。足補正は既定OFFの比較機能である。
モデル実行はPC上で行い、映像や姿勢をクラウドへ送る経路は設けていない。人物検出のNMSを含む処理はWASM、身体・手・足の推論は選択したWebGPU/WASMを使う。検出器は初回・再捕捉時だけ実行する。
2カメラでは元画像座標・カメラ内部外部パラメータ・時刻の対応から三角測量し、再投影誤差・視線交角・正深度で外れ値を棄却する。単眼位置は骨長・相対深度・弱い時系列事前分布から推定し、校正済み多視点の位置と区別する。
遮蔽中は短時間の速度予測と手首・足首等に連動する姿勢保持を使う。経過時間に応じて信頼度を落とし、観測に復帰した点と補完された点を区別する。
足は左右の母趾・小趾・踵と足首から甲の向きを求める。5本の足指は幾何学的な補完であり、それぞれの足指の曲げを独立に画像から観測したものではない。
## 操作
入力Aに動画またはPCカメラを指定し、モデルを読み込む。人物が画面の小部分にいる場合は「範囲を選ぶ」で元映像上のROIを指定する。モデルは初回に取得し、以降は端末内のキャッシュを利用する。
2視点では入力Bに別位置で同時撮影した映像を指定する。録画は時刻差を合わせ、同期確認を有効にする。ライブ映像は撮影時刻が取得できる場合にのみ同期済みとして融合する。
スマホは「スマホをカメラにする」を開く。PCで招待を作成し、スマホへ渡し、スマホの応答をPCへ戻す。外部STUN/TURNは設定せず、映像はWebRTCのLAN経路だけを使う。端末は撮影・エンコード・送信だけを行い、PCの1セッションで2映像を順に推論する。
校正JSONの読込、実測内部パラメータと既知寸法平面4点からの外部校正、設置位置による暫定推定を備える。未校正の相対姿勢を実測メートルとして扱わない。
「計測JSON」は観測2D・推定3D・欠測/補完の区分・処理時間・校正情報を保存する。元動画は含まない。
## オンラインと閉域
初回に静的アプリ、推論ランタイム、ONNXモデルを取得する。先にモデル読込とオフライン準備を完了させると、閉域モードでページからの未キャッシュHTTP要求を遮断する。WebRTCのメディア経路はLAN候補のみを使う。
通信表示の対象はページのResource TimingとWebRTC候補経路である。OS全体のパケット監査やWindows Firewall設定の検証を実施したとは扱わない。
## GitHub Actionsの評価
通常の評価・コード検証・モデル変換・配布物作成はGitHub Actions上で実行する。明示的に依頼された私有動画の実推論はローカルの専用CLIで行い、公開用のブラウザ確認には自作VRMだけを使う。
evaluation/benchmark.pyはMMPose公式の小規模COCO-WholeBody実画像と注釈を使い、全身・手・足別PCK、画素誤差、hand5追加前後、人工遮蔽時の変化を保存する。人物BBoxは正解を利用する診断実験であり、自動検出込みの評価ではない。手ROIは予測点のみから作成する。
evaluation/codec-parity.mjsは実画像のRGBテンソルと実SimCC出力を使い、出荷するJavaScript前後処理を独立したOpenCV/ONNX Runtime経路と比較する。
evaluation/geometry-experiment.mjsは既知の数値条件で校正・三角測量・時刻棄却・前後移動を検査する。数値条件での合格を実カメラの精度達成とは呼ばない。
`evaluation/detector-evaluate.py`は人物検出から全身・手の再推論までを通し、4画像の事前固定対象を採点する。検出の最大候補を使い、正解人物箱を推論に渡さない。`evaluation/foot-evaluate.py`は足モデルの全候補方式と人工遮蔽時の回帰を比較する。
`evaluation/holdout-evaluate.py`は公式COCO-WholeBody v1.0検証注釈のSHA-256を固定し、調整に使用した4画像を除いた32画像を推論前に確定する。人物検出経路と正解人物箱を使う参考経路を分け、通常・手遮蔽・足遮蔽の条件で全採点点を分母に残す。これはルール設計に未使用だった画像での検証であり、既製モデルの全学習データとの重複を排除した主張ではない。画像ID・選択規則・注釈ハッシュはレポートに含める。
`evaluation/panoptic-experiment.mjs`は公開された実録3D動作を取得する。Panopticが取得できない場合はCMUの公式ASF/AMCを使用し、実録の体幹・四肢位置から100/300/1000msだけ観測を消して、補完誤差と単純な位置保持との差を計測する。カメラ画像からの誤差や、指・足指の時系列精度を測ったものではない。
Actions成果物には通常画像と遮蔽条件の数値、画素誤差、未検出数、採否理由を残す。画面のActions実測欄は生成されたJSONだけを表示し、取得できなかったものを未評価として表示する。
CPUでのモデル実行時間はGPUやWebGPUの速度ではない。小標本のPCKはCOCO全体のAPではない。ユーザーの遮蔽映像や2端末での定量精度は、対応する基準位置を持つ実データで別途判定する。
## モデルの配信
BootsTAPIRの3グラフは[Foot-Point-Tracker-onnx](https://huggingface.co/RabbitDaisuke/Foot-Point-Tracker-onnx)へActionsから公開する。Google公式コードと元重みはApache-2.0で、アプリはmanifest・重みのrevisionとSHA-256を固定する。初期3点の意味付け、再帰状態、公式参照との比較は[フェーズ3の測定範囲](docs/phase3-results.md)に記載する。
Actionsが公式ONNXを無変換で取得し、SHA-256と入出力仕様を記録する。Hugging FaceのRabbitDaisuke/Wholebody-Refinement-onnxへアップロードするには、対象リポジトリへのwrite権限を持つHF_TOKENをGitHub Actionsのsecretに設定する。HUGGINGFACE_TOKEN、HUGGINGFACE_HUB_TOKENにも対応する。
人物検出器は同じApache-2.0リポジトリの`person/`へ配置する。FOCUSは元の学習済み重みを検証してONNXへ変換し、AGPL-3.0の`RabbitDaisuke/Foot-Refinement-onnx`へ配置する。変換jobにはアップロードtokenを渡さず、公開jobを分ける。アプリは公開済みrevisionとSHA-256を固定し、取得時に整合性を検査する。
重みはHugging Faceへ配置する。フェーズ2のActions一時成果物は7日、フェーズ3の実測結果・静的アプリ・ローカル配布ZIPは14日保存する。配布アプリの評価JSONと再現用コードはリポジトリとSites版に保存する。

## フェーズの境界
フェーズ3として、実モデルの局所点追跡、録画の順送り、ローカルVRMへの反映、任意のOSCブリッジまで実装する。隠れた全関節・独立した5本の足指の正確な3D運動、完全自動の足裏意味認識、物理GPUでの実時間性能、SteamVR/VRChat実機の動作を達成済みとはしない。
