# 実画像評価の範囲

GitHub Actionsの`Actual-image pose evaluation`で公開画像を実際にONNXへ入力し、正解注釈との2D位置誤差を測る。ローカルやクラウドブラウザの手動テストは行わない。

初期セットはCOCO-WholeBody作者が公開した`evaluation/example_gt.json`と、対応する4枚のCOCO検証画像である。画像IDは785、40083、196141、197388。人物ID順で最大12人を選ぶ。小規模な実画像比較であり、論文の全検証セットAPや実利用一般の精度とは異なる。`workflow_dispatch`の`dataset=val-subset`と`people`で正式検証注釈から対象を増やせる。`val-subset`では初期4画像を除外し、人物IDのSHA-256順でサンプルを固定する。モデルの学習や閾値調整には使用しない。

通常のpushで64人評価を再実行するのは、モデル定義・推論処理・画像評価スクリプト・評価workflowが変わったときだけである。一般のUI・LAN変更は`Application syntax`で構文を確認する。画像評価では追加でRTMDetの実画像1枚を推論し、出荷経路のBGR正規化入力で人物BBoxのIoUが0.5以上になることを確認する。この1枚は一般的な人物検出率の証明ではない。

現在のpush・手動実行の既定モデルは、新候補の`rtmw-l-384`（入力384×288）だけである。完了済みのS/L基準値を同じ変更で何度も再計測しない。過去の比較は手動実行で`models=rtmpose-s,rtmw-l`を指定すれば再現できる。新候補も同一の固定64人・同じ注釈・同じ評価定義で測定し、元モデルの基準値と比較する。

## 比較

RTMPose-S FP32、RTMW-L FP32の全身推論を同じ人物ROIで比較する。さらにOpenCV ZooのMediaPipe手専用ONNXを追加し、同じ画像の手位置が改善するか悪化するかを測る。手の回転ROIは全身モデルの予測した掌7点だけから作る。正解の手位置・手BBoxは手推論へ入力しない。正解の人物BBoxは利用するため、人物検出器の性能はこの評価に含まれない。

元画像と、手または足を灰色矩形で隠した画像を比較する。矩形実験は既知の正解を保持した静止画の入力劣化実験であり、現実の布・人体による遮蔽や時系列追跡の精度とは別の結果として扱う。

## 指標

Body、feet、handsを別々に集計し、平均・中央値・p95画素誤差、人物BBox長辺の5%と10%を閾値とするPCK、手BBox長辺の20%を閾値とするHand PCKを出す。正解注釈が有効であれば、モデルが低信頼でも位置誤差の分母から外さない。信頼度0.25以上の被覆率も独立表示する。Bodyのみ、公式の可視`v=2`と遮蔽`v=1`を分ける。手足の`v`には小数の信頼値が認められているため、整数1/2を遮蔽の定義として流用しない。

モデルURL、revision、SHA-256、実ONNX入力・出力名とshape、選択した人物ID、画像SHA-256、推論バックエンドを`report.json`へ保存する。予測値JSONと、正解・全身モデル・手refinementを重ねた証拠画像も保存する。モデルの巨大なバイナリをActions成果物へ再アップロードしない。

## 3Dと実機の境界

`verify-geometry.mjs`は、異なるカメラ中心・校正・時刻を使った三角測量の数学契約と、予測の失効を検査する。これは既知の合成3D入力による実装検証であり、実カメラでのセンチメートル精度の証拠ではない。実機の2視点動画、本人骨長、撮影位置の正解、LAN端末間通信、RTXのWebGPU速度は、それぞれの実入力があるときに評価する。

`--panoptic-input`を指定した場合は、CMU Panopticの実画像推論から得た2視点観測と既知カメラ校正を、アプリと同じ`dist/geometry.js`の`triangulateJoint`と`dist/tracking.js`の`OcclusionTracker`へ入力する。正解3D座標は評価にだけ使用し、公開レポートには残さない。身体17点と左右の手42点について、利用可能な推定のMPJPE、推定が存在する割合、20/50/100mm以内のPCKを測る。PCKの分母は欠測を含む全有効正解点とし、難しい点を失効させただけで精度が良く見える集計を避ける。

中央8フレームで両手の全視点観測を除去する実験は、画像モデルの遮蔽性能とは分ける。これは実動作の3D正解に対し、時系列補完が観測欠測中にどこまで追従できるかを測る。元の観測・観測除去の両方について、直接三角測量と時系列追跡、全フレームと欠測区間の指標を個別に出す。

## 初回4画像での実測

[Actions run 41374788866](https://github.com/DaisukeDaisuke/Wholebody-test/actions/runs/41374788866)は、コミット`935b396ad3684e12edc4f9ceca059215a755a871`で全job成功した。4画像12人、身体181点・足38点・手210点が有効だった。

| 構成 | 身体平均誤差px | 足平均誤差px | 手平均誤差px | Hand PCK(.20) |
|---|---:|---:|---:|---:|
| RTMPose-S | 6.460 | 8.713 | 6.544 | 32.86% |
| RTMPose-S＋手ROI | 6.460 | 8.713 | 6.119 | 40.48% |
| RTMW-L | 4.380 | 5.183 | 4.084 | 64.29% |
| RTMW-L＋手ROI | 4.380 | 5.183 | 3.949 | 66.19% |

手ROIの採用はSで24手候補中2手、Lで4手だった。灰色で隠した手157点のHand PCK(.20)はSで1.91%、Lで12.74%となり、手専用推論の追加では改善しなかった。Lでは隠した手点の信頼スコア0.25以上の割合が100%だったため、そのスコアを「見えている確率」とみなせない。初回セットでの改善を全ての映像へ一般化しない。後続の64人評価はこの4画像を除外する。

## 初期4画像を除外した64人での実測

[Actions run 41376400694](https://github.com/DaisukeDaisuke/Wholebody-test/actions/runs/41376400694)の`evaluate` jobは、コミット`9f5cb1ca7aea0bf91e82ed8860112b807c03c317`で成功した。固定した64画像64人、身体655点・足111点・手945点を評価した。同runのPanoptic jobはデータ取得で失敗しており、run全体の結論はfailureである。画像評価の成功と動画評価の未完了を混同しない。

| 構成 | 身体平均誤差px | 足平均誤差px | 手平均誤差px | Hand PCK(.20) |
|---|---:|---:|---:|---:|
| RTMPose-S | 13.641 | 19.397 | 22.315 | 52.70% |
| RTMPose-S＋手ROI | 13.641 | 19.397 | 20.860 | 60.53% |
| RTMW-L | 9.358 | 8.323 | 13.208 | 74.92% |
| RTMW-L＋手ROI | 9.358 | 8.323 | 13.540 | 72.49% |

この64人では、Sへの手ROI追加は改善したが、Lへの追加は悪化した。したがって品質側の既定構成はRTMW-Lの全身推論を採用し、手ROIは比較用の選択肢として残す。初回4画像の改善だけでは既定化しない。64人の結果をこの構成選択に使用したため、以後この集合を「構成選択にも一切使用していない最終test」とは呼ばない。追加の学習・閾値調整をする場合は別の固定集合で評価する。

身体の人物PCK(.05)はSで73.28%、Lで83.05%。自然遮蔽ラベル付き身体74点ではLで59.46%、可視身体581点では86.06%だった。手指と足先には同じ可視・遮蔽ラベルがないため、この区別を流用しない。

灰色mask実験では、同じ633手点を原画像と比較した。LのHand PCK(.20)は原画像74.72%からmask後17.22%へ低下した。mask後もスコア0.25以上の点が92.26%あり、全身モデルの高いスコアだけでは遮蔽下の指位置を正しいと判断できない。CPUの全身推論平均はSで41.08ms、Lで149.93msだったが、これはGitHub runnerのCPU値でありRTX/WebGPU速度ではない。

### 手presenceを観測遮断に使う案の検討

既存の推論結果だけを集計し、`presence <= 0.10`を候補に調べた。推論ROIを作れず手モデルを実行していない場合は、presenceゼロとして扱わず別に数えた。

| 全身モデル | 元画像の有効注釈手で低presence / presence取得手 | maskが触れた手で低presence / presence取得手 | ROI未実行（元画像 / mask対象） |
|---|---:|---:|---:|
| RTMPose-S | 10 / 44 | 23 / 27 | 1 / 45、5 / 32 |
| RTMW-L | 11 / 45 | 26 / 31 | 0 / 45、1 / 32 |

maskに対する反応はあるが、Lでも元画像の有効注釈手の24.4%を低presenceとした。例えば人物注釈1751582の左手はpresence 0.0208でも平均位置誤差1.28px、456968の右手は0.0838でも2.08pxだった。低presenceの11手を一律欠測へ変えると、元画像の全945手点を分母に保った人物PCK(.05)は85.40%から67.83%へ低下する。これは元の正しい166点まで失うためである。presenceを既定の可視性ゲートにせず、手ROIの採否にだけ使用する。時間履歴でこの損失を補えるかは、別の実系列評価が必要である。

ここで「元画像の有効注釈手」は自然遮蔽の厳密な可視ラベルではない。また、単に低presence点を指標の分母から外して改善したようには集計していない。

## Panoptic実動画の取得状況

同runの40フレーム・2視点評価は、推論前の配布元到達性確認で停止した。公式CMUのHTTPS接続失敗、HTTPのタイムアウト、掲載ミラーの502・接続リセットを`probe.json`へ保存した。証明書検証を緩和していない。この結果から手指3D精度や実動画遮蔽補完の合格を主張しない。

再取得は`Panoptic multiview evaluation (manual)` workflowへ分離した。既知の外部接続失敗をUI変更ごとに繰り返さず、配布元の回復または利用可能な正式URLを確認したときに手動実行する。過去の失敗runと取得失敗の証拠を残し、取得失敗を成功に置き換える処理は入れない。
