# フェーズ3：映像からローカルVRMを動かす
## 最初の操作
1. 入力Aで動画を選ぶか、PCカメラを開きます。動画・VRMファイルはアップロードされません。
2. 「追跡する範囲」を選びます。全身・手指・足先を扱うときは「全身・手指・足先」、足の映像だけなら「足だけ」を選びます。範囲の切替は推論を停止してから行います。
3. 全身入力の主モデルはRTMW3D-Xです。「モデルを読み込み、開始」を押します。最初の読込ではモデルを取得するための通信が発生します。全入力を足だけにした場合は足用の推論を使います。
4. 必要に応じて、映像上の「人物を囲んで選ぶ」で追跡対象を指定します。全身モデルの人物自動選択は最初に最大の人物を選びます。
5. 「VRMを選ぶ」で端末内の `.vrm` を開くと、実際の推定骨格がVRMの対応ボーンへ反映されます。VRMがなくても推定骨格を表示します。表示欄の選択で「VRM」と「推定骨格」を切り替えられます。
6. ドラッグで視点を回し、ホイールで拡大します。「視点を戻す」で表示中の骨格またはVRMを画面に収めます。
## 足だけの映像
「足だけ」は、全身が映っていない入力を全身検出へ渡さず、足先の画像上の点を使います。「足追跡方式」の既定はBootsTAPIRです。FOCUSが足先の初期位置候補を出し、その候補または手動指定した画像点の移動をBootsTAPIRで追います。BootsTAPIRは指定点の追跡モデルで、どの点が母趾・小趾・踵かの意味付けは初期候補や本人の指定が担います。比較用に「画像フロー」へ切り替えられます。方式変更は推論を停止してから行います。モデルの取得・利用状況は読み込み時の表示を確認してください。
自動候補で足先の点が付かない場合は、「本人の左足／右足」を選び、「足の3点を指定」を押します。映像を止めた状態で、母趾先、小趾先、踵中心の順に3点を指定します。その後は選んだ方式で画像点を追跡します。これは初回の手動指定を使う追跡で、自動検出の成功とは区別します。対象が変わったり見失ったりした場合は指定し直してください。
「初期3点の周辺を拡大」は比較用の固定範囲で、既定はOFFです。ONにすると初期の3点だけから正方形を作り、その範囲内を追います。将来の映像に合わせて範囲は移動しません。足が小さいときに有利な場合がありますが、大きく動いて範囲を外れると追跡できません。本人が囲った範囲がある場合はそちらを優先します。
足の回転は最初に採用した足の角度を基準とした、画像平面内の角度変化です。奥行き、足首の3D回転、上半身の位置、独立した5本の足指の曲がりは、この入力だけでは観測していません。
足だけ・未校正のVRM表示は入力Aを優先します。Bだけを表示したい場合はAを閉じてください。校正済みで時刻が合った2視点は、三角測量の条件が成立すれば別の3D推定経路を使います。
VRMの足ボーンへ反映できた点がある場合も、観測していない上半身は基準姿勢です。モデルが自動で付けた左右は解剖学的な左右として未確認です。手動指定では映像の左右ではなく、本人の左足・右足を選びます。
## VRMファイルと表示確認
VRM 0.x / 1.0 の、テクスチャを埋め込んだバイナリ形式のファイルに対応します。外部画像や外部バッファへの参照があるファイルは、外部通信を行わず読み込みを止めます。`.glb` はVRMの人体情報を持つものに限ります。
[ずんだもん公式モデルの配布ページ](https://booth.pm/ja/items/3733351)などから、配布元の利用条件に沿ってVRMを入手できます。外部配布モデルの本体は同梱していません。「外す」で選択中のVRMを表示から外します。
「サンプルVRM」はこのアプリのコードで生成する、小さなスキン付き人体モデルです。外部配布モデルや私有データは使っていません。ファイル選択を使わずにVRM表示を確認できます。サンプルの読み込みだけでは作った動きを開始せず、実入力か、別操作の表示確認用デモを反映します。
WebGLを利用できない環境では、自動で「CPU簡易描画」へ切り替わります。同じVRMの実ボーンとスキニング後の頂点・面をCanvas 2Dへ投影するため、入力からのボーン反映と視点操作は使えます。テクスチャ、MToon、影、面の重なりと透過は簡略表示です。サンプルVRMは全メッシュを使い、大きなモデルは全体から最大6,000面・18,000頂点を選んで、使用数と上限を画面に示します。表示更新は最大24fpsに制限し、実際の描画速度は「3D表示の更新」で確認します。灰色の骨線は観測されていない部位の基準姿勢を含み、追跡精度の証拠にはなりません。CPU描画への切替は推論backendを変更しません。
「VRMの入手・表示だけを確認」を開き、「表示確認用デモを再生」を押すと、作った動きで表示を確認できます。デモは自動開始しません。紫の「表示確認用デモ」表示が付き、映像の精度評価、計測記録、VRブリッジへの出力には使いません。実入力の推定が届くと実入力へ戻り、「デモを終了」でも元の入力へ戻せます。
推論がまだ始まっていないVRMは基準姿勢で表示します。追跡の欠測が失効した部位も基準姿勢へ戻すため、姿勢が表示されていることだけでは、その部位を現在観測できているとは判断できません。
## 表示と実動画追跡を分けた最小確認
1. 表示を確認するときは「サンプルVRM」を開き、基準姿勢のモデルが出ることを確認します。必要な場合だけ「表示確認用デモを再生」を押し、紫のデモ表示とボーンの動きを確認してから「デモを終了」を押します。この操作は映像追跡の成功確認には含めません。
2. 実動画を確認するときは、端末内で選んだ動画を入力Aへ入れ、「足だけ」と「BootsTAPIR」を選びます。VRMは本人が選んだローカルモデルか自作サンプルを使えます。どちらも動きの入力は実動画にします。
3. 母趾先・小趾先・踵中心が見えるフレームで「足の3点を指定」を押し、本人の左右を選んで3点を順に指定します。録画を確実に順番に解析する場合は「動画を順送り解析」を押します。通常再生ではモデル読込と指定フレームの処理が完了してから再生します。
4. 映像上の3点がそれぞれ指定した部位の動きに付くかと、VRMの対応する足の平面内回転が変わるかを別々に確認します。表示確認用デモの紫表示がないこと、上半身や奥行きが観測済みとして表示されないことも確認します。
5. 推論を停止し、停止状態になって結果の更新が止まることを確認します。停止後の表示は最後の結果です。精度と速度の記録には、選択したモデル・追跡方式・実行backendと実測値を使い、デモの動きや描画fpsを混ぜません。
## 録画の順送り解析
動画ファイルを開くと、その入力の下に「動画を順送り解析」が出ます。現在の表示フレームで停止して必要なモデルを読み込み、1枚の推論が終わってから動画時刻を1/30秒進めます。足の3点を指定した場合も、その停止フレームから開始します。WASMで1枚の処理に数秒かかっても、動画だけ先へ進んで追跡が切れないための機能です。
通常再生は最新フレームだけを処理します。順送りは30Hzのメディア時刻でのサンプリングで、実時間再生ではありません。元動画のネイティブフレームをすべて厳密に復号する保証もありません。現在の動画時刻・解析済み枚数・実際の推論速度を別々に表示し、計測JSONにもサンプリング方式を残します。
「順送りを停止」でその位置に止まります。動画の通常再生、手動シーク、入力の閉じ直し、追跡対象や時刻・校正の変更でも順送りは停止します。途中で動かした動画には、以前のフレームの3点をそのまま再適用しません。必要なら新しいフレームで指定し直します。
2入力を順送りする場合は両方の現在フレームの解析完了を待って進みます。2本の開始時刻を自動で一致させる機能ではないため、同時撮影なら先に時刻を合わせてください。時刻や校正が不確かな入力を、確認済みの多視点3D位置として扱いません。
## 位置と補完の読み方
骨格の色は、校正済み多視点からの3D推定、単眼・人体形状からの推定、遮蔽中の予測を区別します。VRMはこれらの推定をボーンへ適用した表示です。欠測部分を正しく測定できた証拠にはなりません。
RTMW3D-Xが返す相対深度だけで、カメラから本人までの絶対距離は決まりません。未校正のときは骨盤の絶対位置をメートルの実測として表示せず、VRMは表示原点を固定して相対的な動きを反映します。VRMの身長は表示用であり、本人の身長として自動採用しません。尺度が必要な場合は本人の実測身長やカメラ校正を使います。
左右のToesボーンは足先をまとめたボーンです。母趾・小趾・踵の点や甲の向きから、独立した5本の足指の関節角を観測したとは扱いません。
## 2本の動画・スマホ入力
同時撮影した2本をA/Bに入れ、同じ動作の時刻までそれぞれ移動し、「現在の表示フレームを同時刻に合わせる」を押します。時刻を確認したチェックを入れ、「2本を同時に再生」を使います。時刻差や不確実性が許容幅を超えた組は多視点推定へ混ぜず、画面に理由を表示します。
2視点の3D推定には、同じ座標系を使うカメラ校正が必要です。「校正JSONを読む」か、既知の内部パラメータを設定し、2台から見える同じ実寸長方形の4点を左上・右上・右下・左下の順に指定します。仮のカメラ配置は実測校正と区別します。
スマホはPC側の「スマホ接続」から招待を作り、同じLANのスマホで招待リンクを開きます。スマホでカメラを開始し、表示された応答をPCの応答欄へ貼り付けて適用します。2台目は別の招待・応答を作ります。スマホ画面は撮影・送信専用で、VRMや推論モデルを読み込みません。詳しい校正・接続操作は[フェーズ2操作手順](./usage.md)を参照してください。
## 速度の表示
「入力フレーム」は入力映像の更新頻度、「モデル推論」はニューラルモデルを実行したフレームの頻度、「追跡結果の更新」は画像の動きだけで更新するフレームも含む頻度です。「3D表示の更新」は描画の更新頻度で、同じ頻度で推論したことにはなりません。「入力→結果 p95」は入力フレームの取得から処理結果が戻るまでの所要時間です。前処理とモデル実行は直近90フレーム内の中央値を示し、モデルを実行しなかったフレームはモデル時間の中央値から除きます。3D表示のCPU処理はVRM更新と描画要求にかかった時間で、GPU側の描画完了時間ではありません。未取得の測定値はダッシュで表示します。
CPU簡易描画の「3D表示のCPU処理」には、ボーン変形、頂点投影、Canvas 2Dへの描画処理を含みます。WebGL描画の値やモデル推論時間とは処理内容が異なります。
Actions実測欄のデータセット・モデル名を確認してください。別モデルでの診断結果や表示確認用デモを、RTMW3D-Xの実入力精度の結果へ読み替えません。
WebGPUを選んだことや3D表示が60fpsで更新されたことは、60fpsで推論できた証拠にはなりません。端末・モデル・追跡方式が一致する実測のモデル推論fpsと入力から結果までの時間を確認します。
## ローカルVR出力
任意のVR出力を使う場合は同じPCでブリッジを起動し、「ローカルVR出力」のURLと起動時のトークンを入力して「接続」を押します。既定URLは `ws://127.0.0.1:8787` です。トークンは自動保存・計測JSON出力に含めません。
「SteamVR座標校正JSONを適用」で、撮影座標から既知のルーム座標への変換を読み込みます。JSONは `schemaVersion:1`、撮影校正と一致する `worldCalibrationId`、識別用の `roomAlignmentId`、`confirmed:true`、四元数 `rotationXYZW:[x,y,z,w]`、平行移動メートル `translationM:[x,y,z]` を持ちます。適当な恒等変換を校正済みとして使用せず、実際のルーム基準に対応する値を使ってください。
撮影側の絶対位置とルーム側の対応が揃うまで、有効なトラッカー位置を送りません。足だけの2D入力はこの条件を満たしません。SteamVR実機との座標一致は未検証です。手指のボーン反映と全身トラッカーへの出力は別の機能です。
## 使用している表示API
表示には固定版の[Three.js](https://threejs.org/docs/)と[three-vrm](https://pixiv.github.io/three-vrm/docs/)を使い、実入力の推定結果からVRMのnormalized humanoidボーンへ回転を反映します。モデルの入手や実入力の動画・画像を、表示コードへ埋め込む必要はありません。
